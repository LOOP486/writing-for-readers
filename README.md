# writing-for-readers

`writing-for-readers` 是一个面向中文写作的 AI 技能。它负责把口述、零散想法和既有材料整理成自然、清楚、可以直接交付的文本，同时尽量保留作者本人的判断与表达习惯。

它不追求把文章写得更复杂，而是让读者更容易理解：先给出明确判断，再解释原因和作用过程，最后说明它会带来什么结果。写作中会主动清理口述重复、空泛结论、模板腔、术语堆叠和不必要的写作过程说明。

## 两种写作模式

### 成稿模式

成稿模式用于正式回答、文章、方案、报告、分析、邮件和其他可以直接提交的文本。它以自然段组织内容，让标题负责导航，让段落负责完整论述。

这种模式会重点处理以下问题：

- 保留作者真正的观点和个人体验，不把鲜明判断改成四平八稳的公文。
- 建立“判断或现象—原因或机制—实际影响”的论证关系。
- 合并口述中的重复、停顿和自我修正，但不因此遗漏有效观点。
- 区分作者立场与写作过程自述，允许自然使用“我认为”，同时删除“下面将从三个方面分析”等模板表达。

### 条目模式

条目模式用于提纲、要点、需求拆解、汇报速览和结构梳理。除一级标题外，全部正文都放在无序项目符号中，并通过缩进表示包含、解释、因果和展开关系。

条目模式不使用数字编号，也不会把正文写成游离于项目符号之外的段落。每个项目尽量表达一个完整判断，而不是只堆放几个关键词。

```markdown
# 标题

- **核心判断：**一句话说明最重要的结论。
  - 补充这一判断成立的背景或边界。
- **作用机制：**说明对象如何运行。
  - 规则会如何改变人的选择。
  - 这些选择又会形成什么结果。
```

## 如何使用

技能支持自动调用。当主要任务是面向读者的中文写作、改写或润色时，AI 可以根据内容自行判断是否使用，并在成稿模式与条目模式之间作出选择。

也可以在提示词中显式指定：

```text
使用 $writing-for-readers，把这些口述内容整理成可以提交的正式回答。
```

```text
使用 $writing-for-readers，以条目模式整理这份方案。除主标题外全部使用小点，不要数字编号。
```

如果没有指定模式，正式成文默认使用成稿模式；需要快速浏览的提纲和结构梳理默认使用条目模式。

## 安装

将整个仓库放入 AI 工具能够识别的技能目录，并确保目录中直接包含 `SKILL.md`。

Codex 的常用安装位置为：

```text
$CODEX_HOME/skills/writing-for-readers
```

Claude Code 的常用安装位置为：

```text
~/.claude/skills/writing-for-readers
```

也可以直接克隆仓库：

```bash
git clone https://github.com/LOOP486/writing-for-readers.git <技能目录>/writing-for-readers
```

需要同步新版时，在本地仓库中手动执行：

```bash
git pull --ff-only
```

## 文件说明

- `SKILL.md`：自动触发条件、核心写作流程和交付检查。
- `references/paragraph-mode.md`：成稿模式的组织、表达与修订方法。
- `references/bullet-mode.md`：条目模式的格式契约、层级规则和输出示例。
- `agents/openai.yaml`：技能在 Codex 中显示和调用所需的界面配置。
